## Supabase Tables

  pims_observations   — Approved observation records (live audit data)
  pims_staging        — Field captures awaiting review
  pims_audits         — Audit definitions (audit_ref, audit_name)
  sites               — Site/location reference data

**Key columns on pims_observations (relevant for reports and queries):**
  observation_text           — Raw text as submitted by the iPhone shortcut
  observation_text_enriched  — Haiku-rewritten, report-ready version
  legal_reference / legal_ref — CCVS code assigned by enrichment
  ccvs_confidence            — Enrichment confidence score
  enriched                   — Boolean: has Haiku enrichment run?
  enriched_at                — Timestamp of enrichment completion
  review_status              — "Approved" / "Staging" / other
  approved_at, approved_by   — Approval audit trail
  staging                    — Boolean: is this record still in staging?
  site_id, site_address      — Location linkage
  audit_date                 — When the observation was captured
  submitted_by, device_info  — Provenance metadata
  photo_url, photo_refs      — Image references
  prepared_by, recommendation — Report-side fields

For most report queries, you want `review_status = 'Approved'` and
`observation_text_enriched` (not the raw text). The dashboard's Live Audits
tab filters on exactly this.

## Diagnostics

If the client reports that Snap observations are not reaching the dashboard,
or that enrichment is missing, check Railway Deployments → Logs for the
request (`POST /pims/observation/[CLIENT_SLUG]`) and diagnose by status code:

  503  — Supabase URL or service key env var missing in Railway, or typo'd.
         Re-check [CLIENT_UPPER]_SUPABASE_URL and
         [CLIENT_UPPER]_SUPABASE_SERVICE_KEY.
  401  — X-PIMS-Token header in the iPhone shortcut does not match
         PIMS_[CLIENT_UPPER]_TOKEN on Railway. Confirm both.
  422  — Pydantic rejected the payload. Usually because the audit_ref
         contains disallowed characters (spaces, slashes, ampersands,
         punctuation) or exceeds 100 characters. Must match
         ^[A-Za-z0-9_\-]+$. Fix in the shortcut's JSON body.
  No log entry at all — the shortcut's request never reached the server;
         the URL in the shortcut's Text block is wrong.
  Photo appears on dashboard but stays as bare image with no CCVS code after
         ~30 seconds — enrichment did not run. Grep Railway logs for
         "Background enrichment complete for"; if absent, the route is not
         forwarding background_tasks and has regressed. Escalate to Alan.

## Rules

- Never modify Railway environment variables without Alan's confirmation.
- Never delete records from pims_observations without Alan's approval.
- Always use the audit reference [AUDIT_REF] when querying or inserting data
  for this client.
- When constructing a new audit_ref (e.g., for a follow-up audit), it must
  match `^[A-Za-z0-9_\-]+$` with max length 100. No spaces, slashes,
  ampersands, or punctuation — the API will reject with HTTP 422.

  communications.
- If you are unsure about a value or setting, refer to the RPD client setup
  as a reference example.
- Treat the Supabase service role key as secret — never display it in outputs
  shared with the client.
- Do not promise export functionality (PDF reports, XLSX / DOCX exports)
  without first confirming with Alan that the backend handlers exist for
  this client. See "Export endpoints" under Key URLs.
